# 广告过滤与详细诊断

播放器右上角点击“广告过滤”，选择关闭 / 宽松 / 严格，再点“应用到当前播放”；保存为默认，重新加载并尽量保持内容位置与暂停状态。默认仅显示设置和实际过滤摘要，下面的分片、标记 / 复制内容在“详细诊断”中展开。打开面板不暂停视频，遥控器返回先关闭面板。

## 面板内容

- **过滤实际状态**：关闭、非 M3U8、清单已重写、重写失败后回退直链、离线文件等分别显示。回退直链时不把原计划删除的片段数说成已经过滤。
- **当前分片（估算）**：原清单序号、分片时长、分组与过滤后的输出时间范围。
- **来源与文件**：当前估算分片的域名与路径，去掉 URL 查询参数、片段标识和 URL 用户名 / 密码。
- **相邻变化**：与前一保留分片比较域名、分组，以及中间是否有被过滤的分片。
- **保留原因和附近分片**：记录原有规则的实际判定，包括广告路径、短片段、整组异域、样本不足与“删光保护回退”。附近同时显示保留和已剔除的条目。

域名变化是线索，不是已经确认广告。清单中的“疑似广告”仍由既有宽松 / 严格启发式判定，tv.24 在严格模式增加下述受限的分辨率规则，仍属于启发式判断。

## 严格模式的分辨率插播检查（tv.24）

只在选择“严格”时启用，在线播放和下载使用同一路径。关闭与宽松不增加视频头请求，既有时长 / 路径规则不变。

- 适用于至少 24 片、至少两分钟、有结束标记的独立 H.264 MPEG-TS 分片。直播 / 动态清单、加密、分片字节范围、初始化 MAP、fMP4、HEVC、无有效 SPS 等情况不套用本规则。
- 在全片均匀分布的九个位置读取实际 SPS；至少七个样本尺寸完全一致才建立主尺寸。不是把主清单声明的 RESOLUTION 当成实测，也不声称已经检测了所有正片。
- `EXTINF` 的常见时长、分组长度只决定检查顺序。不同长度本身不新增删片；常见时长也不等于已经确认是正片。
- 新增剔除要求区间有 2–16 片、合计 3–60 秒，区间首尾具有 DISCONTINUITY 边界，内部每片均实际读到相同的异常尺寸，前后各两片均恢复主尺寸。按用户选择的严格偏好，即使宽高比相同，只要编码宽或高不同，也纳入此检查。没有前后边界的片头 / 片尾、长时间或不明确的变化保留。
- 每片最多请求前 16 KiB，只解析 TS / PES / H.264 SPS 头，不创建播放器或解码画面。最多三个并发、160 个请求（响应上限合计 2.5 MiB）、八秒调度预算；单请求超时至多两秒，已在途请求受网络超时约束后收尾。首次严格检查可能增加起播等待；进度页提示“正在检查疑似广告分片”。严格解析阶段给起播看门狗增加十秒检查预算；解析完成后重新开始正常的媒体起播超时窗口。
- 超时、未知尺寸、任何内部样本失败或证据不足，都不新增剔除；诊断注明已采样范围和预算不足，不能将未检查区间说成没有广告。原有严格短片段等规则仍可独立判定。
- 成功尺寸使用仅驻内存的 512 项缓存；最近至多 16 份完全相同 URL / 清单内容的分析结果（清单键累计约两百万字符上限，至少容纳当前一份）在进程内固定复用，包括未完整检查的结果，避免原位重新准备视频时因追加发现广告而改变同一播放时间轴。不同签名 URL / 不同清单内容分别分析；不持久化视频头。进程重启或缓存淘汰后需重新检查。
- 过滤后保留返回正片的 DISCONTINUITY，供解码器处理时间戳 / 编码衔接。诊断记录实际新增剔除区间的主尺寸、异常尺寸与判定原因。

这是疑似广告规则，并非语义识别或 AI。正片也可能包含短时不同画幅素材，因此以上证据只能降低误删概率，不能保证零误判。相同尺寸的广告也不会被这一规则识别。

SPS 的独立实现按 H.264 参数集字段读取裁剪后的编码尺寸；结构核对参考 [FFmpeg H.264 参数集解析](https://github.com/FFmpeg/FFmpeg/blob/master/libavcodec/h264_ps.c) 和 [MPEG-TS 解复用](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/mpegts.c)。这里只读头部，不引入 FFmpeg 运行时。

## 分辨率切换后的超分恢复（tv.24）

优先通过严格过滤避免已确认的异尺寸插播进入解码器。对未被检查到的插播或其他模式播放，另有一次有条件的恢复：

1. 只有系统曾回报 `superResolutionChanged(true)`，且已记录当时视频尺寸，才记住可以恢复的尺寸；普通“未生效”不会触发不断重试。
2. HLS `videoSizeChange` 曾离开该尺寸，之后回到该尺寸且超分仍未生效，稳定 300 ms 后只尝试一次 `setSuperResolution(true)`。非致命 5410003 在已有成功历史时不再被当成设备永久不支持；5410004、初始确实不支持和致命播放错误仍按原路径处理。
3. Promise 成功不等于生效。仍只在系统回报 true 后显示“生效中”；若 350 ms 内没有新的算法状态回调，沿用原有兼容处理，以同一个 MediaSource 在当前位置精确重新准备，保留播放 / 暂停状态，音量及声音补偿由准备流程恢复。可能短暂缓冲。
4. 关闭超分、换源、释放、尺寸又离开以及较新的开关请求会取消预约或使迟到操作失效。恢复后不在同一次尺寸变化中循环重启；没有成功尺寸、只是同尺寸高帧率 / 倍速等原因导致 inactive 时也不自动重启。

本地回归覆盖正常回调恢复、错误先于尺寸回调、暂停原位重新准备、Off / 换源 / 释放取消、迟到开启不能覆盖用户关闭，以及缺少确认与尺寸再次变化不重启。本轮不宣称 Mate TV 固件问题已经实机修复，需验证原生事件时序与算法结果。官方接口约束见 [AVPlayer](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-media-kit/arkts-apis-media-AVPlayer.md#setsuperresolution18)。

## 估算范围

在解析时累计原清单和过滤后清单的时长。被删除的分片在输出时间轴占零时长，播放进度通过有序时间范围二分查找，返回原清单序号。保留完整分析数据在普通字段中，面板只观察小型展示对象；仅面板打开时以最多每秒一次的频率更新，不每帧扫描整张清单。

这不是 AVPlayer 的网络请求回调，无法据此声称正在解码的文件一定就是该分片。码流时间戳、续播和 seek 可能造成偏差。播放器时长与过滤后总时长相差超过 max(3 秒, 1%) 时停止估算；此阈值只是偏差保护，不表示剩余估算已经校准。

动态清单、缺少有效时长、超过 20000 片的清单、播放位置超出清单范围、重写失败、关闭过滤、非 M3U8 和离线合并文件，都不会伪造当前分片。关闭过滤和直接播放时不为诊断额外拉取播放清单。

## 手动标记

看到插播广告时点击“这里有广告”。应用立即读取当前播放器进度，保存：

1. 片源 key、影片 ID / 名称、集数、线路、播放器进度和时长。
2. 当时的过滤实际状态与展示信息；可估算时附原序号及附近九个原清单条目。
3. 由原清单分片结构生成的诊断快照，保留时长、分组、来源、保留 / 剔除原因。它不是原始完整清单，不含密钥标签，也不可直接拿来播放。

快照最多覆盖 241 片 / 131072 字符，并明确记录是否截断；能定位时以当前估算位置附近为中心，不能定位时从清单起始截取，不能把后者当成广告附近的实际网络记录。

记录存于应用私有 `files/ad-diagnostics/`，正常情况下保留最近 20 份。以临时文件原子替换，单份 JSON 上限 524288 字符；写入失败会提示保存失败，保留旧记录。“复制最近记录”仅在用户点击时把最近一份记录写入剪贴板，包含影片上下文，方便人工贴到排查工具；没有自动上传、自动发消息或自动跳过广告。

重启后可读取最近记录。换源 / 换集 / 重进会重置当前映射，迟到的旧解析结果不能覆盖新映射；播放资源切换期间禁止标记，避免把旧视频进度记到新条目。

### tv.29 时间戳边界与播放页解析

用户报告多个片源越播越不同步，退出后从原进度重新播放会恢复同步。审计发现旧重写器通常会删去 `EXT-X-DISCONTINUITY`，仅在特定分辨率过滤分支保留；这会丢失源站声明的时钟 / 编码边界。按 [RFC 8216 第 4.3.2.3 节](https://www.rfc-editor.org/rfc/rfc8216#section-4.3.2.3)，时间戳序列变化需要该标记。tv.29 在所有模式保留原标记，删除中间分片后补足返回保留片段的时钟边界，被删除片段携带的边界也向后传递，已有返回标记不重复。判广告和删片范围未因此改动。

另在实际量子播放页复现 `var main` 相对地址被旧兜底逻辑与此前脚本链接拼接，形成包含标记和换行的无效 URL。改为只提取完整的引号内媒体地址，支持相对地址与常见转义；清单端点若返回静态播放页，会在固定层数内跟随其媒体地址，无法识别的 HTML 不再写成 M3U8。Mac 对当前量子、非凡播放页解析后的清单及首片段读取成功；这不替代电视网络栈和实际播放验证。

159 项本地测试通过，包含未命中分辨率过滤时仍保留时钟标记、切片后补边界、前后缀删除、序列头保留、HTML 静态地址提取和拒绝网页伪清单。修复的是已确认的清单 / 地址解析缺陷；渐进音画失步是否完全消失仍待电视长播确认，不采用固定时差或定时重启来冒充自动同步。

### tv.33 同分辨率插播的采样率组合证据

用户在《惊声尖叫7》电影天堂源标记 04:58，原生暂停时间 298787 ms，截图为博彩插播。Mac 对原清单 #75–79 的受限头尾样本确认视频均为 1920×1080，与正片相同；五片音频为 44100 Hz，前后 #73–74 / #80–81 为 48000 Hz，插播区间 298.160–317.227 秒，共 19.067 秒。电视音频服务也观察到从 48 kHz 流切换到新的 44.1 kHz 流。UI 的原片轨道尺寸会继续为 1080p，不能以此排除广告。

严格模式将音轨采样率加入已有受限码流检查：九个分布样本至少七个一致才确定主采样率；要求短区间 2–16 片、3–60 秒、双侧 DISCONTINUITY、时长偏离主分片模式，逐片采样率一致且不同于主音轨，前后各两片恢复主音轨。单纯 44.1 kHz、长时间变化、常规时长、未恢复或任一样本未知，都不新增音轨删片。宽松 / 关闭不执行这些探测。

只识别未加密 TS 的 AAC ADTS；先复用视频的头部 16 KiB，缺少音频时通过 Content-Range 总长度读取明确偏移的尾部 16 KiB，验证返回范围，避免部分 CDN 对负后缀 Range 返回单字节。采样频率索引和帧长的格式依据可核对 [FFmpeg ADTS 解析](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavcodec/adts_header.c)。非支持格式、错误或不完整数据返回未知；不下载完整片段。总预算最多 160 次请求 / 12 秒、并发至多三个；只缓存已解析元数据与本次分析，重准备复用以维持同一播放时间轴。

Mac 的一次全清单实测 11.8 秒 / 86 次受限请求 / 1409024 字节，九个主样本一致，新增命中用户标记的全部五片；另三个区间为疑似结果，未经人工确认，不称作已验证广告。172 项逻辑回归覆盖采样率解析、正常 44.1 kHz、未知 / 未恢复 / 长变化保护及 HTTP 范围验证。原有严格时长规则仍存在，其总过滤计数包含疑似项，不等于真实广告数。
