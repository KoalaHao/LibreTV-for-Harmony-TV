# 影片声音补偿

播放器控制条的“声音补偿”按钮依次选择：关闭（0 dB）、+6 dB、+12 dB，再回到关闭。使用公开的 [AVPlayer.setLoudnessGain](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-media-kit/arkts-apis-media-AVPlayer.md#setloudnessgain21)（API 21 起），音频渲染用途设置为 MOVIE。

这是当前 AVPlayer 的响度增益，不写系统媒体音量，也不把普通 setVolume 的 100% 当成额外放大。按钮在命令已下发、未收到拒绝后保存选择；原生 Promise 未完成时标为“已请求”，不把它当成可听效果或输出增益的确认。当前音频通路明确拒绝时显示暂不可用，并回退当前影片的选择。公开接口不支持高清音频通路，具体能否应用依赖系统服务与音频路由。

设置存于观看记录的 `loudnessGainDb`，以 `sourceKey + vodId` 定位。相同影片同一源再次打开时恢复；同名影片另一源和其他影片各自读取自己的值，默认关闭。同一影片内部换线路或换集继续沿用该观看记录。删除观看记录也删除补偿偏好；关闭观看历史时仅在当前播放会话保留。

在 prepared 后下发保存的增益，独立开始自动播放；换源、重连或超分重建后重新下发当前记录的值。原生请求串行执行，源切换及播放器释放会使旧请求的 UI 回调失效。动态补偿不重建播放器，不主动 seek 或改变暂停状态。补偿目标是放大该视频的整体声音，不能据此宣称已实现对白分离或音质修复。

本地测试覆盖：播放前应用、另一源恢复到 0、暂停中设置不启动播放、不写系统音量、不支持时保留普通播放、迟到结果隔离、观看记录跨读取恢复、普通进度更新保留偏好、无效值与清除历史。实机结果记于 [TV 验收](tv-validation.md)。

## tv.25 原生起播兼容

Mate TV 实测发现可选增益请求可能一直不返回。现在先发出增益请求，独立触发正常自动播放，不等待可选操作结束；单次一秒超时退出“设置中”，以不可用状态降级，并允许后续命令继续。原生播放器恢复自动播放已验证，但不把这一设备的实际增益效果标为通过。

## tv.27 未完成 Promise 的兼容

官方开源实现 [AVPlayerNapi::JsSetLoudnessGain](https://github.com/openharmony/multimedia_player_framework/blob/9f9a285ff489afa66861a85dcc4213336a463b36/frameworks/js/avplayer/avplayer_napi.cpp#L5067) 创建 Promise 后，将响度命令排入原生任务队列，但没有完成该 Promise。它的失败通过 error 事件报告。该源码行为与 tv.25 观察到的悬挂现象一致；没有据此认定电视固件与该提交完全相同。

tv.27 仍等待最多一秒让 Promise / error 报告结果，但没有响应只记为“已请求”，不再自动退回上一档。因此同一影片可以继续选择 +6 / +12 / 关，并保存当前选择。明确的 Promise 拒绝、同步异常或响度 error 会回退；迟到的失败也会更正 UI 与观看记录，旧源的 Promise 不能改写新源。服务死亡等其他媒体错误继续交给播放器错误处理，不当成可忽略的增益错误。此兼容不替换视频解码器，也不改系统媒体音量。

本地回归加入永不完成的原生 Promise、连续切档、迟到拒绝、迟到响度 error、其他媒体错误与换源隔离；实际声音是否放大仍须在 Mate TV 做同一片段对照，不能以按钮文字或原生命令已提交代替。
