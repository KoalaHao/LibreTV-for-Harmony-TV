# 手机 / 电视播放接续

版本：1.10.0-tv.2（versionCode 1100104），API 24+。本版完成了应用接续协议、生命周期和播放器恢复的代码适配及本地测试，尚未做双机实测。

## 使用流程

1. 手机和电视都安装本 fork 的相同新版，签名 / 应用身份须满足鸿蒙接续要求；只升级电视、手机继续使用旧上游版本不会具备此能力。
2. 两端登录同一华为账号。手机开启 WLAN 和蓝牙，电视连接网络，建议处于同一 WLAN。两端系统开启“多设备协同 → 接续”。
3. 首次使用，可在两端 LibreTV 的“我的 → 设置 → 跨设备续播”授权多设备协同权限。
4. 手机播放在线影片，在播放页点击分享图标 → “跨设备续播”，完成授权并查看说明。保持影片播放页，在电视系统出现的接续图标 / 提示中继续观看。支持时也可以从电视接回手机。

应用里这一项负责授权和启用当前播放任务；附近设备发现、目标选择和迁移触发由鸿蒙系统入口负责。它不冒充一个能直接选择电视的自建分享面板。

系统图标能否出现、调试签名是否被系统接续接受以及目标设备的具体入口，仍需要双机验证。没有安装过本版时，不能根据旧版的分享 / 投屏图标推断本功能已经可用。

依据：[华为 Mate TV 应用接续说明](https://consumer.huawei.com/cn/support/content/zh-cn16064472/)、[OpenHarmony 跨端迁移开发指南](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/application-models/hop-cross-device-migration.md)。

## 交接内容与播放行为

通过系统接续通道传送当前影片 ID、集数、集名、线路、播放进度、倍速、播放 / 暂停状态、封面地址和当前集的原始网络播放地址。目标设备重新创建自己的 AVPlayer，重新处理片源并定位到传来的毫秒位置。

- 使用当前集原始地址，避免发送手机广告过滤生成的本地 fd 或回环 HTTP 地址。
- 未配置相同源时仍可尝试播放当前集；没有自动导入或永久保存手机的订阅配置。完整选集与后续换集需要目标端具备对应片源。
- 暂停状态交接后先准备画面与定位，不自动播放；用户继续播放时应用传来的倍速。
- 数据准备阶段不暂停源端。系统迁移成功后默认退出源端任务，并在 Ability 销毁时释放播放器和画中画；迁移失败不会由应用主动停播。
- “系统迁移成功”不等于“对端视频首帧已成功播放”。目标网络不通、临时地址失效或需要额外鉴权时，目标端仍可能显示播放错误。本版没有跨设备首帧确认或持续遥控协议。
- 冷启动在 Navigation 挂载后再打开接续播放页；热启动先释放旧播放任务，再创建新的播放页实例；相同迁移请求不会重复压入播放页。
- 只有可接续的在线播放页才把当前系统任务标为 ACTIVE；首页、未就绪或已出错的播放、离线文件不参与接续。

## 分享、接续与投播

播放页分享菜单包含两个入口：

- **分享影片链接**：保留原有 Share Kit 超链接分享行为；链接按原有协议指向影片和集数，不携带本次接续的网络播放地址与观看进度。
- **跨设备续播**：使用系统应用接续通道，目标是另一台设备上的 LibreTV。

原有 AVCastPicker 系统投播入口保留，但本版没有补完 AVCastController 投播流水线，也不将它标为已经验证的 LibreTV 到 LibreTV 播放接续。

## 协议与生命周期

`PlaybackContinuation` 是平台无关的协议及收发中转。`ContinuationService` 处理运行时权限和任务迁移状态；并按顺序提交 ACTIVE / INACTIVE，防止离开播放页后尚未完成的 ACTIVE 请求覆盖最新状态。

`EntryAbility.onContinue()` 只接受支持本协议的目标版本，将字符串协议写入 `libretv.playback.v1`。接收端处理冷启动 onCreate / 热启动 onNewWant，并在 onWindowStageRestore 中补齐冷启动窗口初始化。使用 Navigation，因此禁用 router 页面栈自动恢复，显式打开播放器。

协议 schema 为 1。接收端验证字段类型、版本、长度、集数、进度和倍速，限制数据为 24K UTF-16 code units 以内，满足官方推荐的迁移数据小于 100KB。只保留约定字段，拒绝本机沙箱、fd、localhost 和回环播放地址。原始媒体 URL 可能包含临时鉴权参数，不写入迁移日志、不塞入公开分享链接。

## 本地验证与待实测

本地测试执行真实协议、Ability 迁移回调、任务状态同步及 AVPlayer 封装逻辑，仅在系统 SDK 边界使用替身。覆盖：

- 影片 / 集数 / 线路 / 进度 / 倍速及暂停状态传输；非法或过大参数拒绝。
- 冷启动暂存、热启动交接、重复请求去重、旧页面清理不影响新页面所有者。
- 旧对端版本、权限拒绝、离线 / 未就绪状态不迁移；准备数据不暂停源端。
- ACTIVE 在途时离开播放页，最终仍收敛为 INACTIVE。
- 接续先定位再按原播放状态决定是否播放；源端销毁释放原生资源。

实机还需验证：系统发现 / 接续图标、授权和签名、手机到 TV / TV 到手机、目标原有播放任务切换、连续交接、迁移失败源端行为、临时地址鉴权、暂停首帧和正常 1× / 倍速续播。详见 [TV 验收清单](tv-validation.md)。本次开发没有连接、查询、安装或修改电视。
